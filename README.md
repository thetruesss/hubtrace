# Hub Trace

Массовая проверка по истории Hub: проходило ли отправление через нужный склад до нужного момента.

## Что это

Расширение для [Hub](https://hub.o3t.ru) — инструмент корректировки расстановки ответственности OnTime.

Разбор спорной расстановки упирается в одну операцию: открыть карточку отправления, зайти на вкладку
«История изменений», пролистать её и глазами найти, был ли предмет на складе X до момента T. На одном ID
это полминуты, на выгрузке в несколько сотен ID — рабочий день.

Hub Trace делает ровно это, но пакетно: на вход список номеров, склад и «потолок» по времени — на выходе
разложенные по трём корзинам номера, детализация по каждому и аналитика по срезам.

## Возможности

**Ввод.** Список номеров по одному в строке или перетащенный файл — `.xlsx`, `.csv`, `.har`. Номера
находятся в файле сами: расширение выбирает столбец с наибольшей долей похожих на ID значений, из HAR
вытаскивает их из тел запросов и ответов. Дубликаты схлопываются.

**Параметры прогона.** Склад задаётся как в Hub — целиком или куском названия. «Отпечаток времени» —
верхняя граница, до которой смотрим историю. Три режима: Турбо (8 потоков), Баланс (5), Глубокий (3) —
различаются числом параллельных вкладок, числом повторов при неполном ответе и таймаутами.

**Быстрый путь.** Главное отличие от ручного обхода и от парсеров страницы. Расширение не листает DOM:
оно смотрит, как сам Hub ходит в свою ручку истории, снимает форму этого запроса и дальше обращается к
ней напрямую, в сессии пользователя. Разница на порядок — сотни номеров за минуты вместо часов.
Быстрый путь под самоконтролем: раз в N номеров результат сверяется с обходом DOM, при расхождении или
протухшем токене расширение само откатывается на DOM, переподнимает токен загрузкой страницы и
возвращается на быстрый путь. Если ручка недоступна, прогон целиком идёт по DOM — просто медленнее.

**Ход прогона.** Служебные вкладки живут в отдельном фоновом окне и не мешают работе. Живой прогресс,
скорость, ETA по прошлым запускам, пауза (`Space`) и стоп (`Esc`), лента событий по каждому номеру.
По завершении — системное уведомление, клик по нему открывает результат.

**Результат.** Три вкладки:

- *Список* — «Есть склад» / «Нет склада» / «Не проверились», с фильтром и копированием каждой корзины.
- *Детализация* — по каждому номеру статус, ЦМН, предыдущий склад и последние строки истории.
- *Аналитика* — настраиваемые панели: последняя ячейка на искомом складе, предыдущий склад, статусы
  отправлений, последние операции, разбивка по дням, часам и пользователям. Плюс сквозной поиск и фильтры.

**Срез по времени.** Потолок можно сдвинуть уже после прогона — итог пересчитается из собранной истории,
заново ходить в Hub не нужно.

**Отчёт.** Выгрузка `.xlsx` со всеми ID и действиями. Файл собирается внутри расширения собственным
кодом (`VC/xlsx.js`), сторонних библиотек нет.

**История прогонов.** Последние пять проверок сохраняются, к любой можно вернуться.

## Обоснование разрешений

### `permissions`

| Разрешение | Зачем |
| --- | --- |
| `storage` | `chrome.storage.local`: настройки (склад, потолок, режим, вид результата, состав панелей аналитики), последний введённый список и итоги последних пяти прогонов. Всё лежит локально в браузере, наружу не уходит. |
| `tabs` | Прогон идёт в служебных вкладках Hub. Нужно их создавать и закрывать, слать в них сообщения, отслеживать закрытие пользователем и переносить в служебное окно (`tabs.create`, `remove`, `sendMessage`, `move`, `query`, `onRemoved`). Отдельно — чтобы по клику на иконку не открывать второе окно приложения, а сфокусировать уже открытое. |
| `scripting` | `scripting.executeScript` — дослать `netprobe.js` и `scanner.js` во вкладку, где контент-скрипты не встали сами: вкладка была открыта до установки или обновления расширения, либо Hub увёл её SPA-навигацией. Инжектятся только файлы из пакета расширения и только во вкладки `hub.o3t.ru`, которые расширение открыло само. Произвольный код не исполняется. |
| `notifications` | Одно системное уведомление в конце прогона. Прогон длинный, окно расширения к этому моменту обычно свёрнуто. Клик по уведомлению открывает результат. |

`chrome.windows` (служебное окно для рабочих вкладок) отдельного разрешения не требует ни в Chrome,
ни в Firefox, поэтому в `permissions` его нет.

### Доступ к хостам

Единственный шаблон — `https://hub.o3t.ru/*`, и в `host_permissions`, и в обоих блоках
`content_scripts.matches`. Это сам Hub: страница, историю с которой расширение и разбирает. Без этого
доступа расширение не делает ничего.

Никаких других хостов в манифесте нет: ни `<all_urls>`, ни доменных wildcard'ов, ни второго origin.

Почему контент-скрипты стоят на `document_start`, а `netprobe.js` — в мире `MAIN`: чтобы снять форму
запроса к ручке истории, обёртку нужно поставить на `window.fetch` и `XMLHttpRequest` самой страницы
до того, как приложение Hub сделает первый запрос. Из изолированного мира до объектов страницы не
дотянуться, а после `document_idle` первые запросы уже прошли. `netprobe.js` только наблюдает: он не
меняет ответы, не трогает разметку и передаёт снятую форму запроса в `scanner.js` через
`window.postMessage` с явным `targetOrigin` — origin самой страницы. Запросы, которые он повторяет,
принудительно ограничены тем же origin.

### Удалённый код

Не используется. Весь исполняемый код лежит в пакете расширения:

- нет `<script src>` на внешние адреса — `app.html` подключает только локальные `xlsx.js`, `sheet.js`, `app.js`;
- нет `eval`, `new Function` и динамического `import()`;
- нет сторонних библиотек и CDN — разбор `.xlsx`/HAR и генерация отчёта написаны в репозитории;
- шрифты (`VC/fonts`) лежат в пакете, Google Fonts и прочие внешние источники не подключаются.

Внешние URL в коде — только адреса карточек `hub.o3t.ru`, которые открываются в обычной вкладке
браузера по клику, и ссылка на профиль автора в `staff.o3t.ru` в подписи интерфейса.

### Данные

Телеметрии нет. Собранная история и результаты остаются в `chrome.storage.local`, отчёт формируется
локально. Расширение не отправляет данные никуда, кроме самого `hub.o3t.ru` — и только те запросы,
которые Hub делает и без него.

## Сборка

```bash
npm run build          # dist/chrome-mv3
npm run build:firefox  # dist/firefox-mv3
```

Исходники расширения лежат в `VC/`, сборка копирует их в `dist/` и подставляет манифест под целевой
браузер. Поле `key` из собранного манифеста удаляется; если оно почему-то осталось, сборка падает.

Для Firefox сборка дополнительно превращает `background.service_worker` в `background.scripts` —
Firefox MV3 service worker'ы в фоне пока не поддерживает.

`public/` — ассеты для стора (иконка и скриншоты). В бандл расширения они не копируются.

Скриншоты в `public/` сняты с реального интерфейса расширения, но на синтетических данных: номера
отправлений, склады, ячейки и логины сгенерированы. Реальных данных Hub в них нет.

## Firefox

`browser_specific_settings.gecko`:

- `id` — `{eeeb1f98-effb-41ee-84b1-b46568f21b0f}`;
- `update_url` — `https://cdn1.ozone.ru/s3/ozon-browser-extensions-public/updates.json`;
- `strict_min_version` — `128.0`. Ниже нельзя: расширение использует `world: "MAIN"` в
  `content_scripts` и в `scripting.executeScript`, а в Firefox это появилось в 128.

### web-ext lint

```bash
npm run lint:firefox
```

Проходит чисто: 0 errors, 0 warnings, 0 notices.

Одно замечание не исправлено и исправлено быть не может — `web-ext lint` без флага `--self-hosted`
выдаёт ошибку `MANIFEST_UPDATE_URL`:

> "update_url" is not allowed. `browser_specific_settings.gecko.update_url` are not allowed for
> Mozilla-hosted add-ons.

Линтер по умолчанию считает, что аддон поедет на addons.mozilla.org, где самообновление запрещено.
Здесь это не так: расширение раздаётся самохостингом с `cdn1.ozone.ru`, и `update_url` задан
требованием платформы. Убрать поле нельзя, поэтому проверка запускается с `--self-hosted` — именно
для этого случая флаг и существует. Остальные три замечания линтера исправлены в коде.

## Локальная разработка

**Chrome.** `npm run build`, затем `chrome://extensions/` → «Загрузить распакованное расширение» →
`dist/chrome-mv3`.

**Firefox.** `npm run build:firefox`, затем `about:debugging#/runtime/this-firefox` → «Загрузить
временное дополнение» → `dist/firefox-mv3/manifest.json`.

Чтобы у локальных сборок был постоянный ID (он нужен для белого списка ИБ), в манифест собранного
расширения добавляется поле `key` с приватным ключом из vault. В публикуемую сборку `key` попадать
не должен — сборка его вырезает.
